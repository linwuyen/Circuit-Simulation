Lesson 04 · 鏈的第③環

決定這一層用狀態機把判定變成動作:每次轉換都要有條件。

上一章的「判定」在這裡被接住。你會看到「請求放電」不是按了就放電——必須同時滿足電壓、電流與通訊健康條件,而且進了 FAULT_LOCK 就不會自己回頭。

目前狀態

INIT
斷開 OPEN

實驗腳本

  1. 1
    按「請求放電」INIT 會先轉到 STANDBY。
  2. 2
    再按一次「請求放電」電壓低於 4150mV 時才會進 DISCHARGE。
  3. 3
    把電流拉到 160A看到 OCP 觸發 FAULT_LOCK。
  4. 4
    按硬體重置學會 FAULT_LOCK 不是軟體自動解除。

對照程式碼

switch(state) {
  case STANDBY:
    if (V > 4250) FAULT;
    if (cmd_on && V <= 4150) DISCHARGE;
    break;
  case DISCHARGE:
    if (I > 150) FAULT;
    if (SPI_Err >= 3) FAULT;
    break;
}
真實對應:這些門檻就是韌體裡的 #define(OVP 4250、放電上限 4150、OCP 150)。狀態存成一個 enum,每個 100µs ISR 跑一次這段 switch;進 FAULT 後不會再被其它分支改回去,這就是「鎖定」。
如果這是你的車:你踩了油門(放電請求),但電池剛充飽電壓偏高,BMS 會「先不放」等電壓回落,而不是冒著過充風險硬接負載。

事件紀錄

狀態機等待第一個 tick。

帶走這三句

  • 狀態機把「判定」變成「動作」,每次轉換都要有明確條件。
  • 放電請求要同時滿足電壓、電流、通訊健康才會成立。
  • FAULT_LOCK 是鎖定狀態,只能靠明確重置離開。
