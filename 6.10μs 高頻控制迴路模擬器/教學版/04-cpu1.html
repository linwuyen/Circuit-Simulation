🧮 CPU1:在 10μs 內把數學算完

讀到感測值之後,CPU 要算出「該輸出多少」。算得越複雜越久,就越逼近截止線。

🎯
這頁只教一件事:CPU1 必須 等 ADC 資料就緒後才開始算,而且要在 10μs 截止前 算完 PID。運算時間越長,撞線風險越高。
生活比喻 PID 就像開車時你的大腦:P 看「現在偏多少」、I 看「偏了多久還沒修正」、D 看「正在往哪個方向變」,綜合起來決定方向盤要轉多少。 這個「想一下」要花時間;想得太久,就會錯過該打方向盤的時機。

🕹️ 動手玩:拖動「CPU1 運算時間」,看會不會撞線

PID 越複雜、處理的資料越多,這條紫色運算條就越長。注意它的右端有沒有頂到 10000ns 紅線。
一輪 10μs 時間軸:
▶️ 開始運算
550 ns
⏹️ 算完於
2050 ns
🟢 餘裕
7950 ns
📊 狀態
👀 觀察提示 運算 1500ns:算完於 2050ns,後面還有一大段時間留給通訊與輸出。把它拉到 9000ns 以上:運算條撞破紅線 → 逾時 → 這一輪根本來不及把結果送出去。運算時間是整條 10μs 預算裡最容易爆掉的一塊。

📌 重點整理

  • CPU1 的工作 = 拿 ADC 的值跑 PID 控制(以及產生命令波形,如正弦),算出這一輪要輸出的控制量。
  • 它有兩個限制:(1) 不能比 ADC 早開始(會拿到舊/壞資料);(2) 必須在 10μs 前結束,還得留時間給後面的通訊與輸出。
  • 所以韌體工程師會斤斤計較每個函式的 CPU 週期數:用查表代替即時計算、用定點數、開編譯器最佳化,都是為了縮短這條紫色條。
💻 對應到真實韌體:典型的控制 ISR 主體
interrupt void adcA1ISR(void) {
    float meas = readResult();              // 取 ADC 結果
    float err  = ref - meas;                // 誤差
    u = Kp*err + Ki*integ + Kd*(err-prev);  // PID 三項
    integ += err;  prev = err;
    writeDAC(u);                          // 輸出
    // 整段必須在 10μs 內跑完;太複雜就會撞線
}

✅ 隨堂小測驗

CPU1 的運算為什麼「不能太早開始」也「不能太晚結束」?
✔️ 正解 A。它被「前面的 ADC 就緒時間」和「後面的 10μs 截止」夾在中間。這個可用區間,就是 CPU1 能花的運算預算。
