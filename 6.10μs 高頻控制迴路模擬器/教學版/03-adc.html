🔌 ADC 與取樣保持:別讀太早

ADC 把「電壓」變成「數字」。但抓值之前要等一下下,等不夠久就會抓到錯的。

🎯
這頁只教一件事:ACQPS(取樣保持時間)就是「ADC 抓值前先等多久」。等太短 → 內部電容還沒充飽 → 讀到的數字是錯的。
生活比喻 像用吸管喝珍珠奶茶:你得 先吸一下下 讓珍珠到嘴邊,太急著一吸就只有空氣。 ADC 內部有個小電容,要花一點時間「充飽」到跟輸入電壓一樣;沒充飽就讀,數字會偏低、失真。

🕹️ 動手玩:拖動 ACQPS(等待時間),看抓到的值準不準

外部精準 ADC(LTC2353)約需 550ns 才充飽。試著拉到 550 以下,看會怎樣。
🎯 真實電壓
2.500 V
📥 ADC 讀到
2.500 V
📊 誤差
0 %
👀 觀察提示 ACQPS = 600ns:讀取點落在曲線「幾乎到頂」的地方,誤差近 0 ✓。拉到 300ns:讀取點落在曲線還在爬升的地方,讀到的值明顯偏低、誤差變大、變紅 ⚠️。這顆假電壓會直接餵給 PID,讓控制器做出錯誤判斷。

📌 重點整理

  • ACQPS = Acquisition Prescale,設定「取樣保持窗口」要多長,用 ADC 時脈週期數表示。
  • 窗口要 ≥ 訊號源穩定所需時間。訊號源阻抗越高、外部 ADC 越精準,需要的時間越長(這裡示意值 ≈ 550ns)。
  • 設太短 = 省了時間但抓到壞值,是高頻控制裡很常見的隱形 bug;設太長則浪費寶貴的 10μs 預算。要剛剛好。
💻 對應到真實韌體:設定某個 SOC 的取樣保持窗口
// ACQPS 以「ADC 時脈週期 - 1」為單位。數字越大,取樣窗口越長。
AdcaRegs.ADCSOC0CTL.bit.ACQPS   = 14;  // = 15 個 ADCCLK,給訊號充飽的時間
AdcaRegs.ADCSOC0CTL.bit.CHSEL   = 0;   // 選擇輸入通道
AdcaRegs.ADCSOC0CTL.bit.TRIGSEL = 5;   // 由 EPWM1 SOCA 觸發(接上一課)
// ⚠️ ACQPS 太小 → 取樣窗口太短 → 高阻抗訊號讀到壞值

✅ 隨堂小測驗

你把 ACQPS 從 600ns 改小到 300ns 以「省時間」。最可能的後果是?
✔️ 正解 B。省下的那點時間,換來的是錯誤的量測值。控制系統「垃圾進、垃圾出」——壞輸入會讓後面再精準的 PID 也算出錯的輸出。
