⏱️ 10μs 截止線:塞得進嗎?

整個課程最核心的觀念。先把它弄懂,後面每一課都是在跟這條線賽跑。

🎯
這頁只教一件事:每一輪的所有工作,加起來必須塞進 10μs(10000ns)。塞不進,就會出大事。
生活比喻 想像你每天早上有 10 分鐘 出門前準備:刷牙、換衣、吃早餐。只要加起來 ≤ 10 分鐘就能準時出門(還能悠閒)。 要是某天拖到 11 分鐘——你遲到了,而且會擠壓到後面的行程。控制迴路的「10μs」就是這個不能遲到的鬧鐘。

🕹️ 動手玩:拖動「一輪要做多少工作」

把它慢慢往右拉,注意越過 10000ns 那條紅線 的瞬間會發生什麼。

📊 狀態
💥 骨牌效應 這一輪沒做完,工作會被推到下一輪;下一輪本來也排滿了,於是越積越多——最後系統崩潰、馬達失控。這就是為什麼絕對不能逾時。
👀 觀察提示 1) 拉到 9000ns:綠色餘裕變很薄,代表「剛好做完、沒有安全邊際」。2) 拉到 11000ns:工作條衝出紅線變紅色,出現骨牌警告。工程上通常會刻意留 ≥ 1000ns 餘裕當緩衝。

📌 重點整理

  • 截止線(deadline)= 10000ns = 10μs。對應 100kHz 的控制頻率(1 秒 ÷ 10μs = 10 萬次)。
  • 餘裕(margin / idle)= 10000 − 一輪工作時間。餘裕越多越安全;為 0 就是「壓線」;為負就是逾時。
  • 逾時的後果不是慢一點而已,是骨牌效應累積崩潰。所以高頻控制的設計重點,就是「每一塊工作要多省時間」。
💻 對應到真實韌體:這條 10μs 由 EPWM 計時器產生中斷
// 100kHz = 每 10μs 觸發一次中斷,所有控制工作都要在這個 ISR 裡跑完
interrupt void controlLoopISR(void) {
    readADC();        // 讀感測
    runPID();         // 運算
    writeDAC();       // 輸出
    // ↑ 這三步加起來必須 < 10μs,否則下一個中斷會疊上來
}

✅ 隨堂小測驗

如果一輪的工作需要 11000ns,會發生什麼事?
✔️ 正解 B。硬體鬧鐘不會等你——時間到就觸發下一輪。沒做完的工作堆積,延遲越來越大,控制就失穩了。這也是為什麼要留餘裕。
