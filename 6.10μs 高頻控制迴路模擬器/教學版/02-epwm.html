⏰ EPWM:精準的硬體鬧鐘

每一輪是誰按下「開始」?是硬體,不是 CPU。這一課看為什麼這很重要。

🎯
這頁只教一件事:用 硬體(EPWM)自動觸發 取樣,每次間隔都一樣準;若改叫 CPU 一直去問(輪詢),間隔會忽長忽短(抖動 jitter),控制就不準。
生活比喻 你要每小時喝一次水。方法A:設鬧鐘——每次都準時整點。方法B:想到才看錶——你在忙的時候就會忘、拖到 1 小時 20 分才喝。 EPWM 就是「方法A 的鬧鐘」,它時間到就自動戳一下 ADC,完全不靠 CPU 記得。

🕹️ 動手玩:讓 CPU「變忙」,看誰的節拍會亂

往右拉 = CPU 越忙。注意上下兩排的節拍點:哪一排不管 CPU 多忙都「整齊」?
每個直條 = 一次取樣的時刻。理想上應該等距排列。
👀 觀察提示 把忙碌度拉到最大:上排(EPWM)依然整齊等距,間隔誤差 0;下排(輪詢)的條子忽密忽疏,間隔誤差(jitter)飆高。取樣時間不一致 → 控制器以為的「現在」是錯的 → 輸出抖動。

📌 重點整理

  • EPWM(增強型 PWM 模組)內建計時器,可設定「計數到某個值就自動發出 SOC 觸發訊號」去啟動 ADC,全程不需要 CPU 介入。
  • 好處是 低 jitter(低抖動):每次取樣間隔幾乎完全相等,控制演算法才能假設「取樣是等間隔的」。
  • 若改用 CPU 輪詢,CPU 一忙就會延後取樣 → 間隔不均 → 控制精度與穩定度都下降。
💻 對應到真實韌體:設定 EPWM 自動觸發 ADC(SOCA)
// 讓 EPWM1 在計數器歸零時,自動發出 ADC 啟動訊號(Start-Of-Conversion A)
EPwm1Regs.ETSEL.bit.SOCASEL = 1;   // 觸發點:CTR == 0
EPwm1Regs.ETSEL.bit.SOCAEN  = 1;   // 啟用自動觸發
EPwm1Regs.ETPS.bit.SOCAPRD  = 1;   // 每個週期都觸發一次
// 之後 ADC 就會「自己」每 10μs 被戳一次,CPU 完全不用管時間

✅ 隨堂小測驗

為什麼控制迴路要用 EPWM 硬體觸發 ADC,而不是讓 CPU 自己抓時間去讀?
✔️ 正解 B。關鍵是「等間隔取樣」。CPU 會被別的工作打斷而延後,造成 jitter;EPWM 是專職計時硬體,時間到就觸發,間隔穩定,控制才準。
