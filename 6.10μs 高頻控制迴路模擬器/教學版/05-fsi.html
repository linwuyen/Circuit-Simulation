🔗 FSI 菊鏈:把資料傳給下一顆晶片

算完之後常常要把結果送出去給別的晶片。傳的資料越多,佔用通道的時間越久。

🎯
這頁只教一件事:FSI 用「菊鏈(Daisy Chain)」把多顆晶片串起來傳資料。Payload(每次傳的位元組數)越大,佔用匯流排的時間越長,吃掉的 10μs 預算越多。
生活比喻 像一排人傳水桶救火:水桶(資料)從第一個人手上,一個傳一個到最後。桶子越大(Payload 越多),每次交接越慢,整排傳完的時間就越久。 而且每次傳遞都有固定的「交接動作」開銷(對應協定的表頭/CRC ≈ 480ns),不管桶大桶小都要做。

🕹️ 動手玩:拖動「Payload 大小」,看匯流排被佔多久

傳輸時間 ≈ 固定開銷 480ns + 每 Byte 約 40ns。佔用超過 10μs 的 30%(3000ns)就要警惕。

🚦 狀態
👀 觀察提示 16 Bytes:利用率約 11%,綠球在鏈上輕快地跑。把 Payload 拉到 120 以上:傳輸時間暴增、條子越過黃色警戒線變黃 → 匯流排被佔太久,留給其他工作的時間被壓縮,可能引發骨牌效應(回想第 1 課)。

📌 重點整理

  • FSI(Fast Serial Interface)是高速序列介面,常用 菊鏈 把多顆 MCU 串接,資料一站一站往下傳,佈線簡單。
  • 每次傳輸 = 固定協定開銷(表頭、CRC 等)+ 與 Payload 成正比的資料時間。所以只傳「真正需要的資料」很重要。
  • 在高頻迴路裡,通訊和運算共用同一個 10μs 預算。FSI 佔太久 → 排擠其他工作。常見對策:減少 Payload、提高傳輸速率、或分多輪傳。
💻 對應到真實韌體:設定 FSI 一次要傳幾個字組
// 傳送的資料量(字組數)直接影響佔用匯流排的時間
FSI_setTxSoftwareFrameSize(FSITXA_BASE, 4);  // 一個 frame 傳 4 個字組
FSI_setTxDataWidth(FSITXA_BASE, FSI_DATA_WIDTH_1_LANE);
FSI_startTxTransmit(FSITXA_BASE);
// payload 越大 → frame 越長 → 佔用時間越久 → 壓縮 10μs 預算
