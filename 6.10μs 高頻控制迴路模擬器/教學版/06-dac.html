〰️ DAC 輸出:一格一格拼出波形

整個 10μs 迴路的「成果」就在這裡。每跑完一輪,DAC 就更新一次,輸出一個點。

🎯
這頁只教一件事:DAC 把數字變回電壓。每一輪迴路只輸出一個取樣點(階梯的一格);許多輪串起來,就成為平滑的波形(例如馬達的電流命令)。
生活比喻 像看影片:每一格畫面都是靜止的,但每秒換 60 格,看起來就連續流暢。 DAC 輸出也是——每一格是一個「定住的電壓」(取樣保持),一秒換 10 萬格,看起來就是一條滑順的正弦波。更新越密(頻率越高)、階梯越細,波形越平滑。

🕹️ 動手玩:改變每週期的取樣點數,並切換「迴路是否出錯」

點越多,藍色虛線(目標)和綠色階梯(實際輸出)越貼合。
目前:迴路正常,輸出乾淨。
目標波形(理想) DAC 實際輸出(取樣保持階梯) 每格階梯 = 一次 10μs 迴路的輸出
👀 觀察提示 把點數降到 6:階梯變粗,和理想正弦差很多(失真),馬達會抖動不順。拉到 64:階梯細到幾乎貼合曲線。再按「模擬迴路出錯」:前幾課任何一步壞掉(ADC 讀錯、運算逾時…),輸出就會跳動失真 → 馬達抖動甚至失控。前面五課的每一個環節,最後都反映在這條波形上。

📌 重點整理

  • DAC(數位類比轉換器)是迴路的出口,把運算結果變成真正的電壓/電流命令給馬達或電源。
  • 取樣保持(階梯):每輪輸出一格、定住到下一輪。更新頻率越高(這裡 100kHz),階梯越細、波形越平滑。
  • 輸出品質 = 前面所有環節的總和。任何一課的錯誤(壞 ADC 值、逾時、通訊塞車)都會讓這條波形失真。所以高頻控制是「環環相扣」的工程。
💻 對應到真實韌體:每輪把控制量寫進 DAC
// 在控制 ISR 的最後,把這一輪算好的 u 寫進 DAC
uint16_t code = (uint16_t)((u + 1.0f) * 2048);  // 轉成 0~4095 的數位碼
DacaRegs.DACVALS.bit.DACVALS = code;          // 輸出一個取樣點
// 下一個 10μs 中斷再更新一次 → 一格一格拼出波形

✅ 隨堂小測驗

DAC 輸出的正弦波看起來像「階梯」,把控制頻率從 100kHz 提高(每週期取樣更多),階梯會怎樣?
✔️ 正解 A。更新越頻繁,每格階梯越短,越逼近連續曲線。代價是每輪的時間預算更緊(回到第 1 課的截止線問題)——這就是高頻控制要在「平滑」與「來得及算」之間取捨。
