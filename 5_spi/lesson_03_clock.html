03. Clock 怎麼推動資料 + 取樣邊緣

為什麼「邊緣」這麼重要？這一課把焦點縮小到一件事：接收端是在 clock 的哪一個邊緣把資料線的值「鎖」進去的。看懂這個，下一課 CPOL/CPHA 就秒懂。

🎯 一句話先懂

資料線（DATA）會一直變，但接收端只在 clock 的某個邊緣那一瞬間「拍照」。拍到的那一刻 DATA 是 0 就記 0、是 1 就記 1。所以資料必須在那個邊緣之前就穩定好。

🪣 生活比喻

像紅綠燈路口的測速照相：車（資料）一直在動，但相機只在「閃光那一瞬間」拍下位置。閃光＝取樣邊緣。如果車剛好在閃光時還在移動（資料還沒穩定），那張照片就是模糊的＝讀錯。

🎮 控制

這就是 CPHA 在決定的事：第幾個邊緣取樣。

本課重點

三句話
  • 更新邊緣：發送端在這個邊緣把下一個 bit 推上資料線。
  • 取樣邊緣：接收端在這個邊緣把資料線的值讀進來。
  • 兩者是不同的邊緣，中間那段時間就是留給資料穩定的 setup。

⚠️ 為什麼會讀錯

把「資料準備」切到「太慢」試試
資料在取樣邊緣時還在變

如果 SCLK 太快、線太長、或中間有 level shifter 延遲，資料可能還沒穩定就被拍照，拍到的是中間的模糊值——這就是高速時偶發錯的主因。下一課會教怎麼算還剩多少 setup 餘裕（margin）。

取樣邊緣選錯（CPHA 不一致）

如果 Master 在上升邊緣送、Slave 卻在上升邊緣讀，等於「邊送邊拍」，會拍到正在切換的值。雙方必須一個負責更新、一個負責取樣，錯開才對。

✅ 自我檢查

「setup time」指的是什麼？
setup time 是「拍照前資料要先站好不動」的時間。不夠的話就會拍到模糊值。下一課的 margin 計算器就是在算這段夠不夠。
