06. Overrun 壓力測試

用接近 C2000 的數字（16-word FIFO）做一次壓力測試：丟一串連續資料進來，比較「無 FIFO / 逐筆 ISR / 一次多筆 / 加 gap / DMA」誰扛得住、誰會 RXFFOVF。

🎯 一句話先懂

只要「CPU 服務一筆的時間 Ts」大於「資料到達的間隔 Ta」，FIFO 水位就會一路爬到滿 → overrun。解法就三招：降速（拉大 Ta）、一次讀多筆 / DMA（縮小 Ts）、加 gap（拉大 Ta）。

🎮 壓力測試設定

進出中斷的存暫存器、判旗標等固定成本。DMA 不受此影響。

建議

怎麼修

跑一次測試後這裡會給對應的修法。

四種方式比一比

同一串資料
方式每筆 CPU 成本能扛的吞吐CPU 負擔適用
無 FIFO最高（每筆即時）最低最重低速、零星資料
FIFO 逐筆 ISR高（每筆一次中斷開銷）中重中速
FIFO 多筆 ISR低（開銷攤掉）高較輕中高速連續
DMA最低最高最輕大量 burst

進階：ISR 一次多讀 vs DMA

觀念程式碼

逐筆 ISR 之所以容易 overrun，是因為每筆都付一次中斷開銷。把 ISR 改成「一次讀到低水位」可以把開銷攤掉；資料量更大時就交給 DMA。

// 每次中斷只讀一筆：開銷沒攤掉，高速時跟不上
interrupt void spi_rx_isr(void) {
    buf[w++] = SpiaRegs.SPIRXBUF;      // 只讀 1 筆
    clear_rx_int_flag();             // 又要付一次進出開銷
}
// 觸發水位設高一點，一次把 FIFO 讀到低水位，開銷被攤平
interrupt void spi_rx_isr(void) {
    while (SpiaRegs.SPIFFRX.bit.RXFFST >= 1)
        buf[w++] = SpiaRegs.SPIRXBUF;  // 一次讀多筆

    if (SpiaRegs.SPIFFRX.bit.RXFFOVF)
        record_overrun();             // 真的溢位才記錄

    clear_rx_overflow_and_int_flag(); // 清旗順序依 TRM
}
// 大量連續資料：DMA 直接搬，CPU 只在搬完才被通知一次
DMA_configure(SPI_RX → ring_buffer, words = 4095);
DMA_start();
// CPU 期間可做別的事，搬完才進一次 DMA done 中斷
C2000 提醒

RXFFOVF 旗標要依你型號的 TRM 順序清，否則下次判斷會失準。實機暫存器名稱以晶片 TRM 為準。

✅ 自我檢查

逐筆 ISR 在 12.5 MHz 會 overrun，下列哪個「最沒幫助」？
FIFO 是硬體深度，軟體 buffer 再大也改變不了「進 > 出」的根本問題。要嘛拉大到達間隔（降速、加 gap），要嘛縮小每筆服務成本（多筆讀、DMA）。
