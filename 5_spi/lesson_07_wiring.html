07. 接線與常見硬體錯誤

很多「讀錯」其實是接線問題，不是程式問題。這一課用一個「故障注入器」把硬體常見坑一次看完：每種錯會出現什麼現象、怎麼確認、怎麼修。

🎯 一句話先懂

SPI 接線三原則：同名對接（不交叉）、一定要共地、線越短越好。多顆裝置時，沒被選中的 Slave 一定要讓 MISO 變高阻抗。

📋 一個完整讀取範例（讀一顆暫存器）

可複製

大多數 SPI 裝置的讀取都是這個節奏：拉低 CS → 送命令/位址 → 送 dummy 收資料 → 拉高 CS。下面三種平台寫法不同，節奏一樣。

// 讀暫存器 reg：送 (reg | 0x80) 代表讀，再送 dummy 收回
uint8_t spiReadReg(uint8_t reg) {
  SPI.beginTransaction(SPISettings(8000000, MSBFIRST, SPI_MODE0));
  digitalWrite(CS, LOW);              // 選中
  SPI.transfer(reg | 0x80);          // 命令：bit7=1 讀
  uint8_t v = SPI.transfer(0x00);  // dummy，收回資料
  digitalWrite(CS, HIGH);             // 結束
  SPI.endTransaction();
  return v;
}
uint8_t spiReadReg(uint8_t reg) {
  uint8_t tx[2] = { reg | 0x80, 0x00 };
  uint8_t rx[2] = { 0 };
  HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_RESET);     // CS 低
  HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, HAL_MAX_DELAY);
  HAL_GPIO_WritePin(CS_GPIO, CS_PIN, GPIO_PIN_SET);       // CS 高
  return rx[1];                                          // 第 2 byte 才是資料
}
// C2000：寫 SPITXBUF 觸發傳輸，等 RX 完成再讀 SPIRXBUF
Uint16 spiReadReg(Uint16 reg) {
  GpioDataRegs.GPACLEAR.bit.GPIOxx = 1;        // CS 低
  SpiaRegs.SPITXBUF = (reg | 0x80) << 8;     // 命令（依字長對齊）
  while (SpiaRegs.SPIFFRX.bit.RXFFST == 0) {}
  (void)SpiaRegs.SPIRXBUF;                    // 丟掉命令期間收到的
  SpiaRegs.SPITXBUF = 0x0000;                 // dummy
  while (SpiaRegs.SPIFFRX.bit.RXFFST == 0) {}
  GpioDataRegs.GPASET.bit.GPIOxx = 1;          // CS 高
  return SpiaRegs.SPIRXBUF & 0xFF;
}

✅ 自我檢查

低速接好好的，一拉高 SCLK 就偶發錯，最可能是？
「低速正常、高速才錯」是典型的訊號完整性 / 時序餘裕問題：縮短線、加地線、串聯小電阻或降速。接反或極性錯會「整個都不對」，不會只在高速錯。
