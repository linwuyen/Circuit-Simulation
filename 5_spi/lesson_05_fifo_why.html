05. 為什麼需要 FIFO

時序全對，資料還是會掉？這一課先用「水桶」建立直覺：FIFO 不是加速器，只是一個緩衝水桶。進水比出水快太久，桶子終究會滿、會溢出。

🎯 一句話先懂

FIFO 是 SPI 與 CPU 之間的一個小佇列。它能吸收短時間的爆量，但不能改變平均速度——只要「平均讀走速度 < 平均進來速度」，遲早溢位。

🪣 生活比喻

水龍頭（SPI 進資料）一直流進水桶（FIFO），你拿杯子（CPU）一杯一杯舀出去。桶子大一點，可以撐過水流突然變大的瞬間；但如果你舀的速度長期跟不上水流，桶子再大也會滿出來——滿出來的水（資料）就永遠回不來了。

🎮 調速度看水位

SCLK 越快、資料越密，進水越大。
CPU 越閒、ISR 一次讀越多，出水越大。
0＝沒有 FIFO（CPU 慢一拍就掉）。

三種狀況

調速度比比看
  • 出 ≥ 進：水位穩定，永遠不會溢。理想狀態。
  • 進略大於出：水位慢慢爬升，FIFO 越大能撐越久，但終會滿。
  • 進遠大於出：很快溢位，FIFO 大小幾乎沒幫助。

⚠️ 初學者最常誤會

「開了 FIFO 就不會掉資料了」

錯。FIFO 只是把「立刻掉」延後成「撐一段時間後掉」。真正的解法是讓平均出水 ≥ 平均進水：降 SCLK、ISR 一次多讀幾筆、加 gap，或交給 DMA。下一課就來實測。

FIFO 真正的價值

讓 CPU 不必每來一筆就被打斷一次——可以累積到半滿才一次處理，大幅降低中斷負擔，也能吸收偶發的爆量。

✅ 自我檢查

進水長期略大於出水，把 FIFO 從 8 格加大到 16 格，會怎樣？
加大水桶只是多買了一點時間。只要平均進 > 平均出，水位的趨勢就是往上，桶子再大也救不了根本問題。
